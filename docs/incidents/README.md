# Incidents, hard failures, and postmortems

Use this area for substantive regressions, outages, data-integrity incidents, recurring test failures or unexpected agent side effects. An incident record identifies observed impact, detection, containment, timeline, likely/confirmed cause, recovery evidence, and preventative follow-up. Avoid for routine bug tickets (use the issue/PR) or ordinary test reports (use `docs/evidence/`). Record private data only in appropriate restricted evidence stores.

Use [the incident template](../templates/incident-report.md). An incident write-up is **evidence**, not project design authority or a substitute for real live monitoring.
